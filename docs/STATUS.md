## Needs human

1. **Integrity list ownership.** `acceptance/test-roms.sha256` (generated by
   `scripts/hash-test-roms.sh`) is what stops a deleted/changed test ROM or PNG
   from silently changing results. Today an agent could regenerate it. Proposal:
   treat it as human-owned like the manifests (add it to the ownership table in
   `acceptance/README.md` and to the `ask` list in `.claude/settings.json`).
2. **Gate script hardening** (`scripts/gate-stage1.sh`, human-owned). Its alloc
   check is a literal grep. `crates/gbc-core/tests/hard_rules.rs` now covers this
   much more thoroughly inside `cargo test`, which the gate runs; optionally
   simplify/strengthen the grep step to match.
3. **Contract text** (`acceptance/README.md`). The runner implements these
   interpretations/additions, recorded in ADR 0007's amendments; please confirm and,
   if you agree, fold them into the README:
   - status precedence crash/timeout > fail > unsupported > no-reference > pass
     (a missing PNG never hides a failure);
   - final frame is white while the screen is blank: LCD off, and the first frame
     after the LCD is turned back on (CGB doesn't display it; SameBoy `frame_skip`);
   - `--gate` without a baseline is exit 2; a baseline from another `roms_release`
     is exit 2; in a full run any baseline entry with no result is a regression,
     dropped only with `--update-baseline --allow-removed`;
   - `--gate` with `--filter/--group/--only-check` scores only the selection
     (the milestone acceptance commands rely on this);
   - new flags `--roms-dir` (still hash-verified) and `--allow-removed`;
   - input changes land at the first instruction boundary at/after their M-cycle
     until M2 adds scheduled inputs.
